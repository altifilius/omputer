# Omputer protocol v1

UTF-8 JSON; times UTC RFC3339, IDs strings. Phone transport requires HTTPS/WSS with exact certificate pinning. REST/WSS authorization is `Authorization: Bearer <deviceToken>`; tokens never in URLs. Error: HTTP status + `{"error":{"code":"...","message":"..."}}`.

## Pairing and devices

Primary pairing uses untrusted DNS-SD `_omputer._tcp.local.` or bounded same-link UDP discovery (`OMPUTER_DISCOVER_V1`, port 47878). Advertisements carry stable server ID, name, port and fingerprint, never credentials. GET `/v1/identity` exposes only public identity metadata. Strict two-sided v2 commitment/reveal at `/v1/pair/request`, `/v1/pair/reveal`, `/v1/pair/claim` requires matching six-digit codes and local PC approval; canonical transcript, expiry/rate limits and no-v1-fallback rules are specified in `PAIRING-V2.md`. The API path prefix remains `/v1`; pairing transcript version is independently `2`.

Secondary PC-app QR bundle: `{version:1,url:"https://host:port",certificate:"base64 DER",fingerprint:"sha256 lowercase hex",code:"one-use secret",expiresAt:"..."}`. QR encodes `omputer://pair?data=<base64url UTF8 JSON>`. POST `/v1/pair` `{code,name}` -> `{deviceId,token,serverName}`. Ten-minute secret consumed atomically once. GET `/health` -> `{name:"Omputer",protocol:1}` reveals no session content.

Device: `{id,name,createdAt,lastSeenAt?,revokedAt?}`. `lastSeenAt` persists the last successful authenticated HTTP request or WSS handshake, with at most one write per minute after the first request; it is not continuous online presence. POST `/v1/devices/:id/revoke` authenticated -> `{success:true}`; ends that device's stream and rejects future requests. Device tokens are hashed on PC and encrypted with Android Keystore on phone.

## Snapshot, continuity, history

GET `/v1/snapshot` -> `{sequence,serverId,serverName,discovery,projects:[],sessions:[],interactions:[],devices:[]}`. HTTP and WSS authoritative snapshots preserve the same identity metadata.

Project: `{id,name,path,goal,summary,nextStep,decisions:[string],updatedAt,sourceSessionId?,memoryOrigin?:"manual"|"agent",sessionCount,pendingCount,activity?}`. Manual/agent durable checkpoint and automatic live activity are distinct. `activity={sessionId,updatedAt,goal,lastAssistantText,nextStep,todos,pendingCount}` is a truthful projection of normal user input, final assistant answer and earliest active/pending task. A turn ending is never a project completion claim. Source and freshness stay visible; empty fields are valid.

Session: `{id,projectId,name,cwd,transport:"rpc"|"bridge"|"archive",status:"idle"|"running"|"waiting"|"disconnected"|"failed"|"closed"|"active-unbridged",model?:{provider,id,name},thinkingLevel?,updatedAt,sessionFile?,todos:[],subagents:[],capabilities:[string],lastAssistantText?,lastUserMessage?,lastError?,hasPendingAsyncWork?,isSettled?}`. Only actually supported controls are advertised. Automatically imported active uninstrumented sessions are `active-unbridged` with no control/resume capability; inactive archives expose history and safe resume, not live control.
Session identity is explicit: `id` is the stable visible daemon session; `journalId` identifies its current OMP journal, `providerSessionId` the provider conversation, and `bindingRevision` the live bridge registration generation. `runtimeSessionId` is a legacy journal identity field, not the visible ID. `writerConnected` is writer liveness, not turn success. `workState` distinguishes `running`, `human_wait`, `queued`, `background`, `turn_error`, `settled`, and `disconnected`; `turnError`, `isStreaming`, `isCompacting`, `queuedMessageCount`, `hasPendingAsyncWork` and `isSettled` retain their separate meanings. A failed turn does not imply a dead writer. Resume validates the canonical root, journal header and inactive ownership lease. Branch/fork/navigation keep the same visible ID, update journal/binding/leaf identity and preserve the original source as archive history; they do not authorize a second writer.


Interaction: `{id,sessionId,projectId,method:"select"|"confirm"|"input"|"editor"|"ask"|"approval",title,message?,options?:[{label,description?}],questions?:[],prefill?,createdAt,expiresAt?,status:"pending"|"resolved"|"cancelled"|"expired",responseTransport:"rpc"|"bridge"}`. `responseTransport` is recorded by the PC from the request's actual source, never chosen by the phone. `questions` preserves OMP ask schema. First valid desktop/mobile answer settles; stale/expired second answers are rejected. Authoritative host pending replay preserves request identity/deadline and reconciles disconnected claims.
`supportsNotes` is true for bridge asks and false for native RPC asks. Nonblank unsupported notes reject `invalid_answer` before claiming the request. Host-pending replay cannot replace the original question, provenance or absolute deadline. Empty multi-selection is valid; single-selection still requires exactly one offered or custom answer. Bridge ask expiry returns the host's recommended answer with `timedOut:true`, rather than manufacturing a user cancellation.


GET `/v1/sessions/:id/messages?before=<numeric sequence>&limit=50` -> `{messages:[{id,role,content:[],timestamp,sequence,revision}],hasMore}`. OMP text/thinking/toolCall/toolResult blocks kept. Stable page ordering; accumulating message updates replace by ID. `sequence` is the chronological paging position; `revision` increases on replacements at that position, so an older HTTP page cannot overwrite newer live text. Native OMP transport negotiates lossless RPC v2 chunks and pages idle history. `session.event:{type:"transcript_reset"}` retires a changed branch before replacement upserts.

GET `/v1/projects/:id/files?path=<relative>` -> `{path,text,truncated}`. Read-only bounded UTF-8, atomically confined beneath canonical registered root; escaping symlinks rejected.

GET `/v1/models` -> `{models:[{provider,id,name}]}` from OMP, no credentials/system prompts/provider transport internals.
PATCH `/v1/projects/:id` `{expectedMemoryRevision,goal?,summary?,nextStep?,decisions?,sourceSessionId?}` -> Project with `memoryRevision` and memory provenance. Revision is required; stale edits return HTTP 409 `memory_conflict`, not last-writer-wins. GET `/v1/projects/:id/memory/history?before=<revision>&limit=50` reads revision history. Manual/agent memory and automatic activity remain distinct.

## Acknowledged commands

POST `/v1/commands` `{id:<UUID>,sessionId?,action,payload:{...}}` records the UUID/request before execution. Persist it on the phone before POST. Final response is `{id,success,data?}` or a structured failure; after the bounded HTTP wait, HTTP 202 `{id,success:true,accepted:true,status:"running"}` means accepted, not completed. Disconnecting HTTP does not cancel the worker. GET `/v1/commands/:id` returns `{id,sessionId,action,status,createdAt,updatedAt,result?}`; `result.data` is the actual completed payload. Status is `running`, `succeeded`, `failed`, or `unknown`. Unknown outcome is not safe to retry under a fresh UUID; reuse/query the original UUID. Missing status returns `operation_not_found`; conflicting UUID requests are rejected. GET `/v1/sessions/:id/operations?before=<sequence>&limit=50` returns `{operations,hasMore,nextCursor}`. GET `/v1/commands/:id/output?after=<sequence>&limit=50` returns `{items:[{sequence,kind,text}],hasMore,truncated,byteLimit,itemByteLimit,itemLimit}`; output is bounded to 1 MiB, 64 KiB/item and 10,000 items. Output is not a second transcript.

- `session.start`: `{projectId,name?,model?:{provider,id},prompt?}`.
- `session.resume`: `{sessionId}`; refuses an existing runtime ownership lease.
- `session.prompt`, `session.steer`, `session.follow_up`: `{message,images?:[]}`.
- `session.abort`: `{}`; does not claim every descendant system process stopped.
- `session.model`: `{provider,modelId}`; `session.thinking`: `{level}`.
- `session.compact`: `{instructions?}`; `session.rename`: `{name}`; `session.refresh`: `{}`.
- `session.bash`: `{command}` explicit command, not terminal keystroke injection.
- `agent.command`: `{agentId,command:"chat"|"kill"|"revive",message?}` actual OMP lifecycle operations.
- `interaction.respond`: `{interactionId,value?:string,confirmed?:boolean,cancelled?:boolean,answer?:object}`. Ask answer: `{kind:"submit",results:[{id,question?,options?:[string],multi?:boolean,selectedOptions:[string],customInput?,note?}]}`; canonical host fills/validates question facts. Approval uses `confirmed`. Full request validation precedes claim.

## Runtime catalog and structured controls

GET `/v1/sessions/:id/commands` returns the current runtime catalog; GET `/v1/sessions/:id/control?view=...` reads `commands`, `state`, `queue`, `tree`, `entries`, `btw`, `plan`, `goal`, `agents`, `agentMessages`, `jobs`, `models`, `effort`, or `usage`. Query `arguments` may be a JSON object; other query values are parsed as JSON where possible. These reads do not start a model request. Responses carry `journalId` and `bindingRevision`. Missing private-runtime controls are explicitly unsupported.

`entries` accepts non-negative `offset` and `limit` (maximum 200), returning `entries`, `nextOffset`, and `hasMore`. `agentMessages` requires an owned descendant `agentId` and optional non-negative `fromByte`; it returns `sessionFile`, `fromByte`, `nextByte`, `reset`, `hasMore`, persisted `entries` and raw `messages`. Child transcripts normally read at most 256 KiB per page; a first record may extend to 2 MiB including its newline. A larger record fails explicitly without skipping history. Incomplete trailing records remain unconsumed; reuse the exact `nextByte` on an explicit later refresh. A cursor beyond a truncated file resets to zero with `reset:true`. Reads cannot select another session's or sibling's transcript.

`session.command` payload contains `{commandId,args:<literal string>,catalogRevision,expectedJournalId,expectedBindingRevision,confirmed?}`. Catalog entries expose source, aliases, description, input/subcommands, `available`, `unavailableReason`, `risk`, `requiresIdle`, and optional `localAction`. Non-read effects require `confirmed:true`; unavailable/TUI-only commands cannot become prompts or arbitrary shell fallbacks. Changed catalogs/identity reject `stale_catalog`/`stale_identity`; idle-required operations reject `session_busy` instead of interrupting implicitly.

`session.control` payload is `{control,arguments:{...},expectedJournalId,expectedBindingRevision,confirmed:true}`. Implemented controls cover `queue.remove/edit/promote`, `jobs.cancel`, `todo.append/start/done/drop/rm`, `btw.ask/cancel`, `goal.create/resume/pause/drop`, `plan.enter/cancel/review/approve`, `tree.navigate`, `branch`, and `fork`. Explicit targets and current plan-review revision are validated; stale queues/jobs/entries/plans reject rather than silently selecting replacements. Successful control results include the authoritative post-operation `journalId`, `bindingRevision`, and `leafId`. Branch additionally returns `selectedText`/`selectedImages`, `cancelled`, and `sessionFile` inside the command result. Restoring selected composer content is not permission to send it.

## Read-only project inspection and export

GET `/v1/projects/:id/tree?path=&query=&cursor=0&limit=100` browses a bounded root-confined tree. GET `/v1/projects/:id/changes` and `/diff?path=<relative>` inspect changes and per-path diffs without staging or committing. File/tree reads reject root escape; unsupported, binary, oversized, symlink and unavailable repository cases must remain visible rather than invoking an arbitrary terminal command. GET `/v1/search?query=...&projectId=...&sessionId=...&cursor=0&limit=50` searches the persisted transcript FTS index, optionally scoped. GET `/v1/sessions/:id/export?format=markdown|json` exports a bounded text projection, not raw provider/session state: user/assistant/system text only, redaction, up to 2,000 messages, 32 KiB/message and 768 KiB projected content, with truncation reported. Redaction is not a guarantee that conversation text contains no secrets; review before sharing. GET `/v1/diagnostics` exposes local component/update diagnosis, not credentials.

## Event stream

WSS `/v1/events?after=<sequence>` with authenticated handshake. Journal envelope `{sequence,type,sessionId?,projectId?,data,createdAt}`. Types include `snapshot`, `session.updated`, `session.event`, `message.upsert`, `interaction.pending`, `interaction.resolved`, `project.updated`, `operation.updated`, `operation.output`, `notification`, `device.revoked`. Replay then **one** caught-up authoritative snapshot at the same watermark, then incremental live events; later watermark changes do not resend the complete snapshot. Ping/pong liveness; revoked device gets explicit terminal state. Android accepts equal-watermark authoritative snapshot. Snapshot and cursor are tied to pairing identity; re-pair clears previous server content.

Android obtains an authenticated snapshot before subscribing and starts WSS at that exact snapshot sequence, so old transcript replay does not delay current decisions. Open conversations reload after reconnect. The PC keeps full history for paginated reads; normal appended/updated archive history preserves message positions/revisions and emits only changed rows. Actual shortened/reordered/diverged branches still emit `transcript_reset`. Raw `message_start`/`message_update`/`message_end` are not sent again as duplicate `session.event` payloads when their materialized `message.upsert` already carries the content.
Sequence numbers are monotonic watermarks, not contiguous integers. Superseded complete `message.upsert` revisions may be coalesced; unique messages, branch resets, notifications, runtime events, decisions and command outcomes remain retained. Existing journals compact incrementally during replay in persisted batches; freed SQLite pages are reusable, not automatically vacuumed. Total authoritative history is not capped by an arbitrary retention cutoff.


Notification: `{id,kind:"question"|"approval"|"turn_done"|"error"|"connection",title,body,sessionId?,interactionId?}`. Generated locally on Android; no push provider. Approval opens detail, no blind lock-screen permission action.

## Local OMP bridge

Mode-0600 Unix socket `<stateDir>/bridge.sock`; mode-0600 secret `<stateDir>/bridge.token`; owner-only state directory. Register JSONL `{type:"register",token,managed?:bool,managedSessionId?,session:{id,cwd,name,sessionFile?,model?,thinkingLevel?,status,todos,subagents,capabilities}}` -> `{type:"registered",sessionId,projectId,memoryRevision,bindingRevision}`. Registration is authenticated; revision/binding values are daemon-issued. Managed IPC owns extension dialogs/subagent/checkpoints; native RPC owns built-in tool dialogs, session commands and transcript. Terminal IPC owns both. No hosted Collab relay.

Bridge -> daemon: `{type:"event",sessionId,event}`, `{type:"state",session}`, `{type:"interaction",sessionId,request}`, `{type:"interaction_end",sessionId,id,status}`, `{type:"response",id,success,data?,error?}`.

Each extension instance owns one dialog bridge for its lifetime. Session switches/branches close pending dialogs through their original session/transport, restore UI wrappers, then install a fresh active binding without recursion. Closed retained wrappers transparently delegate to their original UI; they cannot create abandoned pending requests. Independently invoked identical questions retain distinct IDs; no content-based deduplication is used.
Native tool replies use the immediate RPC control frame `{type:"extension_ui_response",id:<original question>,responseId:<command UUID>,value?|confirmed?|cancelled?|answers?:[]}`. `ask` maps submitted results to `answers` in canonical question order. The bundled runtime acknowledges `responseId` after delivering to the pending callback, or rejects a stale ID; the PC closes the stored interaction only after that acknowledgement. Bridge-owned dialogs continue through `interaction.respond` on their original bridge.
Daemon -> bridge: `{type:"command",id,action,payload}`.
Checkpoint: `{type:"checkpoint",id,sessionId,data:{goal,summary,nextStep,decisions:[string],expectedMemoryRevision}}` -> correlated `{type:"response",id,success,data?,error?}` after local persistence. The bridge caches the registered memory revision and advances it only from acknowledged checkpoint results. The model-facing `omputer_checkpoint` tool schema remains `{goal,summary,nextStep,decisions}`: it has **no** `expectedMemoryRevision` argument; the authenticated bridge supplies it. Conflicts fail visibly instead of overwriting newer phone memory. Essential tool success requires acknowledgement; guidance adds no model request. IPC reconnect alone never answers a host dialog; authoritative pending replay preserves stable identity.

## Local update and listener lifecycle

Authenticated Unix admin actions `update.prepare` and `update.cancel` reserve/release update admission. Preparation is idempotent and returns `{prepared:true,managedRpcSessions:0}` only when no managed child or acknowledged command remains in flight. The reservation blocks new commands/sessions; active native processes are never inferred dead from a disconnected status. The desktop applies updates only to its authenticated app-owned service or exact fallback child. Legacy daemons without this handshake remain staged until a safe normal service start.

The automatic LAN listener persists its port privately (`lan-port`, initial default 8787); explicit service overrides are honored. Route changes rebind HTTPS and discovery in the same daemon, retaining App, IPC, native children, pending pairing and TLS/server identity. An occupied saved port yields a visible error and retries the same endpoint rather than silently changing firewall targets.
