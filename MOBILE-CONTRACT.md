# Android / Flutter boundary

Flutter uses `MethodChannel('omputer/connection')` and `EventChannel('omputer/events')`. Native Kotlin owns HTTPS/WSS transport, exact DER certificate pinning, encrypted device credentials, foreground/background connection, cached snapshot, sequence cursor and Android notifications. No Dart network calls on Android; no duplicate sockets. UI remains usable with cached data.

WSS frames are processed on the OkHttp reader with network backpressure, not an unbounded executor. Snapshot state uses immutable shallow copy-on-write; transcript events do not parse the snapshot from disk. The main-thread channel coalesces state and same-message revisions; its journal queue is bounded to 128 events / 512K characters. Overflow emits `history_reset`, so Dart reloads authoritative PC pages rather than displaying a partial branch. Dart retains live updates only for conversations already opened.

Before opening WSS, Android fetches the pinned authenticated current snapshot, fences it against connection/pairing changes, records its exact watermark in memory, invalidates stale cached message pages and subscribes only to events after that watermark. Pending decisions come from the snapshot immediately instead of waiting behind the whole journal. `history_reset` invalidates/reloads already-open Dart transcripts, including after an old in-flight page finishes; unopened histories remain PC-paginated. Credentials and PC history are not deleted.
Disposable disk cache writes run on a separate worker, debounced 250 ms; they never turn an accepted command into a failure. Response pages are indexed and limited to 80 entries / 24 MiB total / 2 MiB per entry; snapshot checkpoints are limited to 8 MiB, pending cache work to 1 MiB. Process death can lose the newest cache checkpoint; reconnect obtains an authenticated fresh snapshot before WSS and uses its watermark. Credentials still commit synchronously and are not subject to cache eviction. Re-pair/forget fences queued/in-flight work and clears the previous identity's cache.

An acknowledged decision immediately settles the latest native and Flutter snapshot objects. Duplicate in-flight responses are rejected locally; delayed pending snapshots cannot reopen accepted answers. A failed post-command refresh reports connection state separately, not a failed answer. `supportsNotes:false` excludes note fields from native RPC asks because that runtime does not preserve them; bridge asks preserve separate context notes.

Project and session lists capture their activity order when first shown. Subsequent snapshots replace live row content without sorting existing IDs again by their changing `updatedAt`. Filtering/searching does not reset those positions. Newly discovered IDs enter once in recent-first order; removed IDs are released. Reopening a screen establishes a fresh recent-first order.


Single-choice `ask` forms expose **Özel yanıt** as a radio choice, mutually exclusive with offered labels. Selecting custom clears the offered selection; selecting a label leaves a custom draft inactive and omits it from the submitted payload. Empty custom text cannot submit. Multi-choice forms use a separate custom checkbox, permitting labels plus a nonblank custom answer only while that checkbox is selected. Context notes are not additional answers. `allowCustom:false` hides and excludes custom mode. Canonical raw `select` dialogs still accept only offered labels.

Methods:
- `discover` args `{enabled:bool}` -> `{scanning,error?}`. Native DNS-SD and bounded local broadcast discovery publish untrusted candidates, never credentials.
- `pairRequest` args `{computerId,name,background:bool}` -> `{requestId,verificationCode,expiresAt,serverName,fingerprint}`. Native completes strict `PAIRING-V2.md` commit/reveal, captures the server commitment before client reveal, validates the opening and derives the code locally. No pairing secrets or commitments cross into Flutter.
- `pairPoll` -> `{status:'pending'|'approved'|'denied'|'expired'}`; only approval installs credentials and clears the previous server cache atomically. Cancellation/revision guards reject stale network results.
- `pairCancel` -> clears local pending state and cancels tracked calls; no silent pairing. The PC request expires without approval.
- `previewBundle` args `{bundle}` -> validated `{serverId?,serverName?,url,fingerprint,expiresAt?,existingPair}`. Local-only: no network or trust/cache mutation. Flutter requires explicit identity/fingerprint and replacement consent before `pair`; cancelling an external link preserves the existing pair and content.
- `pair` args `{bundle:<QR payload or omputer://pair URI>,name:<device label>}` -> `{deviceId,serverName,url}`. Secondary camera/deep-link recovery only; native validates the exact certificate and consumes the ten-minute one-use bundle. Primary onboarding is nearby-PC selection and matching-code approval, not JSON paste.
- `connection` no args -> `{paired:bool,connected:bool,background:bool,backgroundRunning:bool,notifications:bool,batteryExempt:bool,revoked:bool,serverName?:string,url?:string,lastError?:string}`. `connected` means the authenticated WebSocket is open, not merely that an HTTP snapshot was fetched.
- `snapshot` -> last cached PROTOCOL snapshot or `{sequence:0,serverName:'',projects:[],sessions:[],interactions:[],devices:[]}`.
- `request` args `{method:'GET'|'POST'|'PATCH',path:'/v1/...',body?:object}` -> parsed JSON. Errors are PlatformException with code from API and human message. Paths must be relative `/v1/`; no arbitrary remote URL.
- `connect` args `{force?:bool}` -> connection map; `force:true` explicitly replaces stale transport. Foreground-only connection is allowed before background permission is granted.
- `background` args `{enabled:bool}` -> connection map. User chooses ongoing visible connected-device service. Do not promise delivery after Android force-stop.
- `notifications` -> request POST_NOTIFICATIONS permission, return bool.
- `batterySettings` -> opens OS battery-optimization page, no blanket permissions silently.
- `forget` -> deletes local pairing and cache, stops service. Server revocation is separate.
- `theme` args `{mode:'system'|'dark'|'light'}` -> persists local preference.
- `preferences` -> `{theme:'system'|'dark'|'light',appVersion:string,buildNumber:string,protocol:1}` from the installed Android package.
- `localState` -> `{identity,sections}`; `localStateSet` `{section,key,value}` updates `pins`, `read`, `lastMode`, or `notificationPreferences` (null removes a key).
- `draftLoad` `{key}` -> draft object or null; `draftSave` `{key,value}` and `draftDelete` `{key}` commit authoritative local drafts. Session keys are `session:<visible-id>:<mode>` (for example `session:xyz:session.prompt`); prompt/steer/follow-up modes remain distinct. Complete prepared image bytes belong in drafts, not expiring picker URIs. Restored branch text/images must not overwrite an existing composer draft or send automatically.
- `draftList` (no arguments) -> complete identity-scoped `{key:draftValue}` map, used to retain shared native attachment resources while another durable draft still references them.
- `operationSave` `{operation}` persists/merges UUID operation records; `operationList` returns records; `operationRemove` `{id}` removes a record. Save UUID and immutable request **before** POST. Reusing a UUID with another request fails. Running/unknown is not final success; query the PC's `/v1/commands/:id` and merge the final result. Final `succeeded`/`failed` records do not regress to pending states. A delayed acknowledgement must not erase a newer composer draft.
Final draft cleanup uses the locally persisted `draftSubmission` snapshot/revision, not the current editor by default. Only final success clears that exact snapshot; a newer revision, different mode, running/unknown outcome or failed command retains it. Successful branch results restore the same visible session's prompt draft once; conflicting or late results are stored separately with `branchRestore`/`draftEffect` metadata and require explicit review. These local metadata fields are not wire payloads. Host-returned image data is bounded/decoded before restoration and does not receive a fabricated native attachment ID.
- `pickImages` `{camera?:bool}` opens the system document picker or explicitly permissioned camera; cancellation/denial returns an empty list. `sharedImages` consumes identity-scoped shared imports; share intents never send a prompt automatically. Prepared rows are `{id,mimeType,data:<base64>,width,height,bytes}`. `removeAttachment` `{id}` removes native-imported resources, not arbitrary restored host image IDs. JPEG/PNG/WebP/GIF only, 1 MiB per image, eight images / 2 MiB aggregate imported storage, dimensions up to 16,384 and 25 million pixels. Pairing changes fence picker/import completion.
- `shareExport` `{text,mimeType?,filename?}` writes a private temporary file and opens the Android share chooser with a scoped FileProvider read grant; allowed MIME types are `text/plain`, `text/markdown`, `application/json`, maximum 8 MiB UTF-8. The user chooses the receiving app; no automatic upload occurs.

Durable state is separate from disposable HTTP cache: identity is `<serverId-or-fingerprint>:<deviceId>`, with private identity-hashed storage, atomic replacement and fsynced file writes. Drafts and operation records allow 6 MiB each; identity state totals 10 MiB, at most 1,000 operations, preference values 64 KiB and keys 512 characters. Storage/full/corruption errors are surfaced; do not report a draft or operation saved after failure or silently replace it with an empty object. Forget/re-pair clears old identity state and attachments. These guarantees do not promise survival of device storage loss or a remote wipe.

Event channel envelopes:
- `{type:'discovery',data:{computers:[{id,name,url,fingerprint}],scanning,error?}}`. Existing-server rediscovery may change only URL after proving the original server ID and exact stored certificate; an independent bounded probe worker does not block interactive requests.
- `{type:'connection',data:<connection map>}`.
- `{type:'snapshot',data:<snapshot>}` after initial refresh and relevant state changes.
- `{type:'history_reset',data:{}}` after snapshot-first reconnect; discard stale open transcript state and reload its latest page without letting old in-flight pages overwrite the new generation.
- `{type:'event',data:<PROTOCOL journal event>}`. UI applies message upserts to open conversation and refreshes snapshot state as needed.
- `{type:'navigate',data:{sessionId?,interactionId?,bundle?}}` from notification tap or `omputer://pair` deep link. Handle pending intent on startup as well.
- `{type:'navigate',data:{sharedImages:true}}` offers explicit return-to-composer or session selection without consuming imports, changing typed drafts, submitting commands or popping the current reading route. The composer imports only after the user selects **Paylaşılan görselleri ekle**. `{shareError:string}` displays a recoverable image-import error without leaving the current route. Notice/session-selection callbacks are fenced to the current pairing identity.

Flutter production uses the native adapter; widget tests may inject deterministic state but no synthetic default data ships. App name Omputer; Turkish interface; preserve PRODUCT.md, PLAN.md, PROTOCOL.md and `.impeccable/surface-briefs/android.md`. Notification replies enforce the same deadline, identity and semantic command-success checks as app responses. Revocation cancels authenticated work, decision notifications and the foreground service; it does not promise a remote wipe of previously cached content.
